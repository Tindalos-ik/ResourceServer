# 文件上传



## 设计思路

文件传输必须满足以下几个条件

* 限制文件大小(不超过4G)

* 长连接传输(效率高，支持大文件)

  > 文件传输不允许任何数据丢失，并且需要保证数据包到达顺序，而且TCP有流量控制和拥塞控制，更适合文件传输

* 客户端和服务器都知道传输进度，以保证支持断点续传(后续实现)



先实现单线程处理版本，再实现多线程的

```cpp
//发送数据槽函数
void TcpClient::slot_send_msg(quint16 id, QByteArray body)
{
    //如果连接异常则直接返回
    if(_socket->state() != QAbstractSocket::ConnectedState){
        emit sig_net_error(QString("断开连接无法发送"));
        return;
    }

    //获取body的长度
    quint32 bodyLength = body.size();

    //创建字节数组
    QByteArray data;
    //绑定字节数组
    QDataStream stream(&data, QIODevice::WriteOnly);
    //设置大端模式
    stream.setByteOrder(QDataStream::BigEndian);
    //写入ID
    stream << id;
    //写入长度
    stream << bodyLength;
    //写入包体
    data.append(body);

    //发送消息
     _socket->write(data);
}
```

发送格式`id + bodylength + 文件流数据`

bodylength是4个字节，所以文件最大是4G

客户端选择文件后，点击发送会把文件切分成固定大小的报文发送

```cpp
void MainWindow::on_uploadButton_clicked()
{
    // 设置按钮不可点
    ui->uploadButton->setEnabled(false);
    QFile file(_file_path);
    if(!file.open(QIODevice::ReadOnly)){
        qWarning() << "Could not open file:" << file.errorString();
        return;
    }
    
    QFileInfo fileInfo(_file_path); // 用完整路径构造
    int total_size = fileInfo.size();
    int last_seq = 0;
    // 计算分块大小
    if(total_size % MAX_FILE_LEN){
        last_seq = total_size  / MAX_FILE_LEN + 1;
    }else{
        last_seq = total_size / MAX_FILE_LEN;
    }
    
    // 读取文件内容进行发送
    QByteArray buffer;
    int seq = 0;
    while(!file.atEnd()){
        // 每次读取2048字节，分块传输
        buffer = file.read(MAX_FILE_LEN);
        QJsonObject jsonObj;
        // 将文件内容转换位Base64编码
        QString base64Data = buffer.toBase64();
        seq++;
        jsonObj["md5"] = _file_md5;
        jsonObj["name"] = fileInfo.fileName(); //提取出文件名
        jsonObj["seq"] = seq; // 报文序列号
        jsonObj["trans_size"] = buffer.size() + (seq-1)*MAX_FILE_LEN; //已经传输的大小
        jsonObj["total_size"] = total_size;
        if(buffer.size() < MAX_FILE_LEN){
            jsonObj["last"] = 1;
        }else{
            jsonObj["last"] = 0;
        }
        jsonObj["data"] = base64Data;
        jsonObj["last_seq"] = last_seq;
        QJsonDocument doc(jsonObj);
        auto send_data = doc.toJson();
        emit TcpClient::GetInstance()->sig_send_msg(ID_UPLOAD_FILE_REQ, send_data);
    }
}
```

## 断点续传

断点续传通过借助MD5(或更常见的SHA-256)来确认已传部分和最终文件是否正确

* 断点续传：上传/下载中断后，从已完成的位置继续传，核心是记录偏移量，分片编号和已完成分片

* MD5：文件内容的摘要/指纹，用于识别内容和校验完整性

  > MD5是一种哈希算法，全程 Message Digest Algorithm5 消息摘要算法5
  >
  > 它会把任意大小的数据，例如一个文件，一段文本，计算成固定长度的32位十六进制字符串
  >
  > 常用于文件完整性校验，文件去重，上传任务标识

* SHA-256，和MD5类似，不过它是生成64位十六进制字符串



常见组合方式

* 秒传/去重

  客户端先计算整个文件的MD5并询问服务端是否已有该文件，已有无需上传，没有开始分片上传

* 续传定位

  客户端带上MD5作为上传任务标识，请求服务端查询已上传的分片或偏移量，然后仅补传缺失部分

* 完整性校验

  上传完成后，服务端计算合并后文件的MD5，与客户端提供的MD5比较

* 分片校验

  也可每个分片带一个MD5，服务器逐片验证，避免某个分片传输损坏后仍被合并
